Benchmark methodology

The publication workflow runs a deterministic synthetic workload against a disposable PostgreSQL service after each push to the default branch. It measures the merged source revision and publishes its aggregate JSON report with the rebuilt site.

Matched modes

EFS_FULL stores encrypted payloads and protected search tokens. PLAINTEXT_CONTROL stores generated plaintext values and raw n-grams solely as a synthetic comparison control. Neither mode uses customer data.

Measurements

The report separates completed throughput, warm p50/p95/p99 latency, final-match recall and precision, no-match false positives, failures/timeouts, indexing throughput, PostgreSQL relation sizes, and JVM/database/host context. Both modes use the same generated records, labels, query mix, candidate limit, database configuration, and concurrency settings.

Limits

These runs are repeatable indicators, not service-level guarantees. Runner noise, JVM scheduling, caches, and PostgreSQL scheduling affect results. No numeric performance threshold is currently approved; PR comparisons report deltas without blocking on timing.

For the full corpus, fixture, and privacy contract, see BENCHMARKING.md.
